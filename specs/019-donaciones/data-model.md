# Data Model: Donaciones

## Entities

### Donation

Represents a donation transaction to one of the two Mercado Pago accounts.

**Attributes**:

| Field | Type | Required | Description | Validation |
|-------|------|----------|-------------|------------|
| id | String (UUID) | Yes | Primary key | `@id`, `@default(uuid())` |
| full_name | String | No | Donor's full name | Nullable. Null = display "Anónimo" |
| email | String | No | Donor's email | Nullable. No uniqueness validation |
| amountCents | Decimal | Yes | Donation amount in COP cents | Minimum 2000, integer value |
| state | DonationStatus | Yes | Current donation state | Default: `pending` |
| account | DonationAccount | Yes | Target Mercado Pago account | Enum value |
| externalReference | String | Yes | Unique reference for reconciliation | Format: `DON-{account}-{uuid}` |
| paymentId | String | No | Mercado Pago payment ID | Nullable. Set from webhook |
| metadata | Json | No | Raw webhook payload for audit | JSONB. Ley 1581 compliance |
| createdAt | DateTime | Yes | Creation timestamp | `@default(now())` |
| updatedAt | DateTime | Yes | Last update timestamp | `@updatedAt` |

**Indexes**:
- `[state, account]` - For filtering donations by status and account
- `externalReference` - Unique, for lookup

**Relationships**: None (standalone entity)

**State Transitions**:
```
pending -> confirmed (webhook: payment approved)
pending -> rejected (webhook: payment rejected)
pending -> cancelled (webhook: payment cancelled)
```

Once out of `pending`, state cannot change (idempotency protection).

### DonationStatus (Enum)

Possible states for a donation:
- `pending` - Initial state, preference created, awaiting payment
- `confirmed` - Payment approved by Mercado Pago
- `rejected` - Payment rejected by Mercado Pago
- `cancelled` - Payment cancelled by user or expired

### DonationAccount (Enum)

Target Mercado Pago accounts:
- `LA_CONVENCION` - La Convención account
- `BARRANQUEROS_UTP` - Barranqueros UTP account

## Prisma Schema

```prisma
model Donation {
  id                String          @id @default(uuid())
  full_name         String?
  email             String?
  amountCents       Decimal         // COP cents, minimum 2000
  state             DonationStatus  @default(pending)
  account           DonationAccount
  externalReference String          @unique
  paymentId         String?
  metadata          Json?           // Raw webhook payload
  createdAt         DateTime        @default(now())
  updatedAt         DateTime        @updatedAt

  @@index([state, account])
}

enum DonationStatus {
  pending
  confirmed
  rejected
  cancelled
}

enum DonationAccount {
  LA_CONVENCION
  BARRANQUEROS_UTP
}
```

## Validation Rules (Zod Schema)

```typescript
// Backend schema (donaciones.schema.ts)
const donationSchema = z.object({
  fullName: z.string().optional().nullable(),
  email: z.string().email().optional().nullable(),
  amountCents: z.number().int().min(2000, "El monto mínimo es 2000 COP"),
  account: z.nativeEnum(DonationAccount),
});

// Frontend schema - same structure, can share types via API
```

## Business Rules

1. **Minimum Amount**: 2000 COP (2000 cents = 20.00 COP)
2. **Amount Type**: Integer cents (no decimals)
3. **Anonymous**: `fullName = null` → display "Anónimo" in UI
4. **Email**: Optional, no validation beyond format, no uniqueness
5. **External Reference**: Generated by backend, format `DON-{account}-{uuid}`
6. **Idempotency**: Webhook processing only updates if current state is `pending`
7. **Metadata**: Raw webhook payload stored as-is, never logged

## Database Considerations

- **Table name**: `donations` (snake_case, Prisma converts to plural)
- **UUID**: Use `uuid()` for id, consistent with project convention
- **Timestamps**: `TIMESTAMPTZ` for createdAt/updatedAt
- **JSONB**: metadata field for flexible webhook payload storage
- **Index**: Composite index on `[state, account]` for common queries
